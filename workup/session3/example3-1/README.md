# Example3-1

In this example we will use vagrant to set up three ubuntu machines to demonstrate both DHCP configuration and DNS configuration

## Vagrant configuration

Our [Vagrantfile](./Vagrantfile) defines three ubuntu 24 machines called , `ubuntu_1` and `ubuntu_2`

`ansible_controller` will be our DHCP server and our Ansible controller node. 
(It will also be used as a DNS server in later experiments).

All of the machines are connected to the NAT network so that we can SSH into them using `vagrant ssh`

A new internal network is also created with the name "dhcp_network". 

Internal networks are only visible to the internal guests and not to the host.
They do not have an internal DHCP server.
(For more information see [https://developer.hashicorp.com/vagrant/docs/providers/virtualbox/networking](https://developer.hashicorp.com/vagrant/docs/providers/virtualbox/networking))

Normally VirtualBox generates virtual MAC addresses by combining a fixed vendor prefix with three randomly generated bytes.
* The Prefix (OUI): The first three bytes (24 bits) are always set to 08:00:27. This Organisationally Unique Identifier (OUI) historically belonged to Innotek GmbH (the original creator of VirtualBox) or PCS Systemtechnik / Cadmus, but is universally recognized by network tools as an Oracle VirtualBox Virtual NIC.
* The Random Suffix: The remaining three bytes (24 bits) are generated randomly using a pseudo-random number generator when a new virtual machine or network adapter is created.

In this example, we do not want generated MAC addresses, so we assign specific MAC addresses to each machine.

The `ansible_controller` is given an IP address `192.168.100.254` and a unique MAC address `080027FFFFA1` on this network using the Vagrantfile line

```
ansible_controller.vm.network "private_network",  ip: "192.168.100.254", virtualbox__intnet: "dhcp_network",  mac: "080027FFFFA1"
```

`ubuntu_1` and `ubuntu_2` will be machines which we will give IP addresses using DHCP, so we give them both MAC addresses, `080027FFFFA2`, `080027FFFFA3`.

Vagrant requires us to specify an IP address so we give them a bogus `0.0.0.0` IP address - but this will be replaced.

```
ubuntu_1.vm.network "private_network",  virtualbox__intnet: "dhcp_network", ip:"0.0.0.0",  mac: "080027FFFFA2"

...

ubuntu_2.vm.network "private_network",  virtualbox__intnet: "dhcp_network", ip:"0.0.0.0",  mac: "080027FFFFA3"
```

As previously, all the machines will be configured with `admin` and `ansible` users with password `minad1234`

The `ansible` accounts will also have SSH authentication keys.

To start the lab use:

```
cd example3-1
vagrant up 

```
(this may take some time to start)

To see the machines running use

```
vagrant status
Current machine states:

ansible_controller        running (virtualbox)
ubuntu_1                  running (virtualbox)
ubuntu_2                  running (virtualbox)

```
Log into the `ansible_controler`, change to the `ansible` user and make sure you can ssh to the `ansible_controller` on address `192.168.100.254`.
(accept any host keys)

```
vagrant ssh ansible_controler
sudo su ansible

ssh 192.168.100.254

# exit from the machine if you can log in.

```
